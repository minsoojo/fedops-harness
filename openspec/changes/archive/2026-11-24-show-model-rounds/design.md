# Design

## Context

worker는 Claude Code의 stream-json에서 도구 이름과 호출 ID, 반환 여부를 추출한다. 호스트는 이를 timeline.jsonl에 추가하고 뷰어는 주기적으로 다시 읽는다. 이 기록에는 모델 요청을 보낸 시각과 회차별 응답 본문이 없다.

## Goals / Non-Goals

실시간 화면과 재조회가 같은 기록에서 같은 회차를 재구성하도록 한다. 첫 버전의 표시 단위는 완성된 응답이다.

## Decisions

- 모델 요청의 송신 경계를 관측한다. Apply의 첫 검증은 키 없는 replay 서버에서 요청을 받은 채 응답을 보류하고 뷰어가 대기를 표시하는지 확인하는 것이다. Claude가 실제 송신을 알리는 신호를 제공하면 그 신호를 사용한다. 제공하지 않으면 worker 내부의 로컬 전달 계층에서 주 에이전트의 메시지 생성 요청을 관측한다. 토큰 계산 등 보조 요청은 제외한다. 도구 반환 직후나 첫 응답 조각 수신 시각으로 송신 시각을 추정하면 대기 구간을 잘못 표시한다.
- 요청마다 실행 안에서 증가하는 번호를 부여한다. 응답이 완성되면 공개된 텍스트 및 도구 요청 블록을 순서대로 기록한다. 도구 결과는 호출 ID로 원래 회차에 연결한다. 같은 도구의 동시 호출도 각각 구별한다.
- 브라우저에서 회차별 행과 호출별 가지를 그린다. 응답 본문은 일반 텍스트로 렌더링하고, 사용자가 펼친 상태를 새로고침 주기 사이에 유지한다. 인증 헤더나 내부 추론 블록은 수집 대상에서 제외한다.

## Risks / Trade-offs

- 전달 계층이 응답을 버퍼링해 Claude 실행을 지연시킬 수 있다 → 전송은 스트리밍을 유지하고 화면 공개만 응답 완료까지 보류한다.
- 도구 오류가 발생해도 모델이 다음 회차에서 복구할 수 있다 → 개별 도구 오류와 실행 전체의 실패를 구분한다.

## Migration Plan

호스트와 뷰어가 새 이벤트와 기존 도구 타임라인을 모두 읽도록 한 뒤 worker를 갱신한다. 회차 정보가 없는 과거 실행은 기존 타임라인으로 연다. worker를 이전 버전으로 복구해도 같은 조회 경로를 사용한다.
